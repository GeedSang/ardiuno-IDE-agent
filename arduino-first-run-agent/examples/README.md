# Arduino IDE 首次运行守护 Agent：可复现实验案例

这些案例都来自同一份“声音传感器 + NeoPixel 灯带”正确代码。请一次只打开一个文件夹中的 `.ino`，不要同时打开多个同名工程。

## 01_正常基线

现象：选择 Arduino UNO 和实际端口后，编译、上传都成功。

用法：点击侧栏“环境检查：主板与串口”，确认能看到 USB 串口；再点“编译检查：当前项目”和“上传验证：运行实物”。

## 02_编译错误_缺少分号

故意修改：`Serial.begin(115200);` 删除分号。

预期：编译失败。把错误日志粘贴到“错误诊断：粘贴日志”，Agent 应指出 `setup()` 附近缺少分号，并建议只补回这一处。

## 03_端口板型_上传配置

代码保持正确，故意在 IDE 顶部选择错误板型或错误端口。

预期：编译可能成功，但上传失败。Agent 应先区分“代码没问题”和“环境配置错误”，提示重新选择 Arduino UNO 与真实 USB 串口。

## 04_库依赖_缺少库

故意把 `Adafruit_NeoPixel.h` 改成一个不存在的库名。

预期：编译失败。Agent 应识别为库依赖问题，提示安装 Adafruit NeoPixel，而不是修改灯带逻辑。

## 05_传感器引脚_行为异常

故意修改：实际接线仍是 A0，但代码改读 A1。

预期：可以编译、上传，串口数值基本不随声音变化。Agent 应对照“代码引脚—接线引脚”关系，提示先确认传感器信号线是否接在 A1；修复方式是改回 `A0` 或把线移到 A1。

## 06_阈值逻辑_灯光无响应

故意修改：模拟读数范围是 0~1023，却用 `900` 作为过高阈值。

预期：可以编译、上传，但灯带几乎一直熄灭。Agent 应读取串口样本，发现数值范围与阈值不匹配，建议先采样再设定阈值，例如用 `value > 500`，而不是直接更换硬件。

## 建议汇报顺序

先运行 01 证明正确路径，再依次打开 02、03、04、05、06 制造错误。每次只改变一个条件，记录：错误类型、Agent 建议、用户需要确认的动作、最终是否成功上传。05、06 用来展示“能上传不等于行为正确”，Agent 需要结合串口数据和接线信息给出诊断。
