# Arduino 项目 Agent

面向 Arduino 初学者的 IDE 内项目助手。它把模糊想法逐步整理成硬件方案、结构化接线和完整代码，并通过 Arduino CLI 安装依赖、针对目标开发板真实编译，在失败时保留原需求、硬件、接线和代码上下文继续自动修复。

> GitHub 仓库沿用课程早期名称 `ardiuno-IDE-agent`；插件和文档中的产品名称使用正确拼写 Arduino。

## 安装

1. 下载最新 `.vsix`。
2. 将 VSIX 放入当前 Arduino IDE 安装渠道使用的 Theia 插件目录；不同安装渠道的目录可能不同，请先备份原插件目录。仓库中的 `install.ps1` 目前只负责本地构建检查，不会猜测或覆盖未知安装路径。
3. 重启 Arduino IDE。
4. 右侧会打开 Arduino Agent 项目看板；也可点击编辑器顶部的 `⚡ Arduino Agent 看板（打开 / 关闭）`。

插件默认启动时创建新的空白 Arduino 草稿并打开看板。可在看板的“启动设置”中分别关闭这两项，不会删除旧项目。

## 从想法到可编译项目

1. 选择“我知道要用哪些硬件”或“先帮我选择硬件”。
2. 初学者模式会提供多种硬件方向、用途说明、外观参考与购买搜索入口，不把模糊需求强行固定成唯一答案。
3. 用户确认硬件和详细方案后，Agent 生成结构化 `ProjectSpec`：主板、元件、接口、接线、行为、风险、依赖和验收标准。
4. 代码模型根据锁定的硬件与接线生成完整 `.ino`，禁止擅自增加未选择的传感器或执行器。
5. Agent 自动安装开发板核心与 Arduino 库，执行目标 FQBN 编译。
6. 编译或行为门禁失败时，Agent 携带完整上下文多轮修复，不要求初学者重新输入全部内容。
7. 代码通过后显示完整接线核对；用户确认实物接线后才能上传。
8. 上传后由用户确认真实效果。没有实物证据时不会声称项目已经运行成功。

## 核心能力

- 支持本地 Ollama、OpenAI 和其他兼容 API；规划、代码、审查模型可以分别配置。
- AI 服务保存前执行真实代码生成与长代码修复测试，避免“连接成功但无法完成项目”。
- 结构化硬件契约校验供电、端子、总线、引脚占用、驱动和电平兼容性。
- Fritzing 端子只作为辅助证据，不能覆盖官方数据手册和内置硬件契约。
- 未知型号缺少可靠端子资料时明确阻止生成，不让 AI 自信猜接线。
- 自动安装库和开发板核心，并显示名称、来源、版本、许可证、进度和失败原因。
- 静态质量、目标板编译、仿真和实物验证分开记录，前一级通过不自动证明后一级。
- 自动修复保留原需求、硬件选择、接线、代码、编译日志和历史记录。
- 项目状态保存到 `.arduino-agent-state.json`；重新打开工程可恢复对应进度。
- 社区分享包自动排除 API Key、本机绝对路径、串口地址和临时文件，并保留 FQBN、库版本、接线、来源和“未经过实物验证”声明。

## 初学者界面

- 右侧项目看板与代码并排显示，所有主要输入和确认都在同一大区域完成。
- 深蓝电子实验台主题区分 Agent 操作、用户选择和风险信息。
- 启动设置、AI 设置、硬件选择、方案修改、上传确认和自动修复均在看板中完成。
- 顶部文字入口和看板内“收起 Agent 看板”按钮可随时打开或关闭 Agent。
- 所有按钮、消息接收器和 Webview 主题覆盖都有自动化完整性测试。

## 可信度边界

看板分别展示结构化接线、代码静态检查、目标板编译、仿真和实物验证状态。编译通过只证明源码可为目标板构建，不证明电源安全、导线接对或设备达到真实效果。普通 USB 不能看见 VCC、GND 和信号线；高电流负载仍需正确的独立供电、共地、驱动和保护器件。

## AI 与隐私

- 本地 Ollama 通常不需要 API Key，需求和代码可留在本机。
- 云端服务需要服务商自己的 API Key；网页版会员不等于 API 额度。
- API Key 使用 IDE SecretStorage 保存，不写入项目、日志、社区包或仓库。
- Agent 不下载、缓存或重新发布淘宝卖家图片；购买入口只执行搜索。
- 硬件图片无法可靠匹配时使用明确标注的通用示意图。

## 创作历程

### 1. 从错误解释到真实工具执行

早期版本只能解释编译错误，且可能编译错目录。之后改为读取真实 `.ino` 工程、FQBN、Arduino CLI 输出和错误位置，让“通过”来自工具证据而不是 AI 自述。

### 2. 从单一案例模板到通用项目规范

声音感应灯最初用于验证链路，但固定模板无法覆盖不断变化的项目。当前版本使用统一 `ProjectSpec`、硬件合同和行为门禁，让随机方案走同一条生成、校验、编译与修复流程。

### 3. 从一次生成到闭环修复

早期错误后需要用户重新描述。现在失败状态保留全部上下文，初学者只需选择继续修复、修改硬件、修改需求或查看技术错误。

### 4. 从权威推荐到引导式选择

模糊需求不再直接得到唯一“必需硬件”。Agent 先给出不同实现方向、取舍和外观参考，由用户逐步选择，再形成详细方案。

### 5. 从左侧树状栏到统一项目看板

旧 TreeView 与右侧页面重复且割裂流程，现已删除。项目输入、硬件选择、设置、接线、代码证据和修复动作统一在右侧看板，编辑器顶部保留清晰的开关入口。

### 6. 从“编译成功”到分层可信度

当前版本不把编译、仿真和实物运行混为一谈。来源、许可证、构建环境和验证证据随项目保存，方便社区成员理解结果到底验证到了哪一步。

完整版本记录见 [CHANGELOG.md](./CHANGELOG.md)。

## 开发与验证

```powershell
npm install
npm test
npx vsce package --allow-missing-repository
```

测试包含工作流恢复、多项目静态门禁、硬件合同与来源、AI 响应修复、Webview 脚本、产品流程，以及命令、按钮、消息接收器和主题覆盖完整性检查。这些测试不能替代真实硬件验证。

## 离线硬件图片扩展包

```powershell
node scripts/build-fritzing-pack.js D:\path\to\fritzing-parts D:\ArduinoAgentData\hardware-packs\fritzing-core
node scripts/merge-fzpz-pack.js D:\path\to\parts D:\ArduinoAgentData\hardware-packs\fritzing-core "来源名称" "来源网址" "图片许可证"
```

扩展包保留来源、网址和许可证。型号含糊或多个候选同分时不会冒充准确实物照片。
